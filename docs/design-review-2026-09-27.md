# 设计走查报告（2026-09-27，第三轮 · 以产品设计总监视角）

走查对象：conduit-bend-calc v1.2.2（Expo Web 桌面视口截图 14 张 + 组件源码）。
结论：功能与计算已扎实，视觉问题集中在三处结构性缺陷，已在 v1.2.3 全部修复。

## P0：首页图标换行（渲染级 bug）

- 现象：3-Point Saddle / 4-Point Saddle 的图标 `'⋀⋀'` / `'⋀⋀⋀'` 在 44px 宽、28pt 字号的容器里换行，
  首页渲染成上下堆叠的 2–3 个尖角，看起来像字形损坏。
- 修复（v1.2.3）：图标改为 `'⋀'`（三点=单峰）/ `'⋀⋀'`（四点=双峰），语义与弯形对应；
  `numberOfLines={1}` + `flexShrink: 0` + 图标槽 widen 到 48px，杜绝任何换行可能。

## P1：宽屏下内容全幅拉伸（Web/桌面/平板横屏）

- 现象：所有屏的 ScrollView 内容容器无最大宽度，1920px 视口下卡片、结果区、输入框被拉成通栏，
  大量死白，工具感全无。
- 修复（v1.2.3）：10 个屏的内容容器统一加 `width: '100%' + maxWidth: 720 + alignSelf: 'center'`。
  手机（<720px）渲染与之前逐像素一致，零回归风险。

## P1：弯管机选择器挤占首屏（7 个计算屏共性 UX 问题）

- 现象：品牌→型号→管径三级选择器约占 400pt 纵向空间，每个计算屏都要滚过它才能看到真正的输入框；
  但用户极少更换弯管机——高频控件被低频设置挤到首屏之外。
- 修复（v1.2.3）：BenderPicker 默认折叠为摘要行（`Ideal 74-026 1/2" EMT` + `R 4.3125" · take-up 5"` + 展开箭头），
  点按展开完整选择器。计算逻辑零改动。

## P0 回归：宽屏下图解 SVG 溢出内容列（加 maxWidth 后暴露）

- 现象：`BendDiagram` 用 `windowWidth - 32` 定 SVG 宽度；内容列收窄到 720px 后，
  宽视口下 SVG（如 1887px）溢出卡片，绘制内容偏到列外右侧、视觉上卡片留空。
- 修复（v1.2.3）：改用所在容器的 `onLayout` 实测宽度（回退窗口宽度），图解永远填满卡片。
  纯函数 `buildBendDiagram` 契约不变，T23 回归测试不受影响。

## 有意不做的

- 字体/配色体系：navy `#0F2B46` + 金 `#F4C317` 已有明确的工具品牌感（DeWalt 式），不 churn。
- 中英混排（英文标题 + 中文说明）：这是产品语言策略问题（目标用户是美国电工，理应英文优先），
  不属 UI 走查范畴，建议发版前单独决策：上架美国区用纯英文。
- 深色模式：theme 已就绪但尚未真机/模拟器验证，列入下一阶段补验，不在本次改动。
